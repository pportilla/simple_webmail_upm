UPM Mail: instant-mail foreground service

This continuous Android screen recording demonstrates version 1.0.1 (code 3): a user enables instant mail, sees its ongoing notification, receives synthetic mail while the app is in the background, opens the notification, and stops the service by selecting manual checking.

Open the MP4 directly · Release identity and verification record

Demonstration scope

The unchanged signed release APK was generated from the final Play AAB. The separately configured adult mailbox uses local GreenMail IMAP/SMTP behind verified TLS 1.3. This is a loopback TLS fixture, not the built-in offline sample account. Built-in sample mail does not start the foreground service. Its temporary CA is trusted only in the disposable Android emulator; localhost port mappings connect the emulator to the loopback-only fixture. App TLS verification and production authentication were not modified. All mail is fictional.

This demonstrates actual IMAP IDLE, notification delivery and service stopping. It does not establish UPM authentication, external-provider delivery, reviewer mailbox access, Google approval or general device compatibility. Mailbox setup, passwords and PIN entry are not included. Captions were added outside the captured screen; the app interaction is continuous.

Recorded steps

  1. 0:00 Exact release 1.0.1 (code 3). Local synthetic TLS mailbox; no UPM connection.
  2. 0:09 Open Settings and choose Check for new mail.
  3. 0:25 User selects Instantly (push).
  4. 0:29 The app is now in the background; IMAP IDLE stays connected.
  5. 0:42 Ongoing notification explains the connection and how to stop it.
  6. 0:48 Inject one synthetic message through authenticated TLS SMTP.
  7. 0:50 Real new-mail notification arrived while app remained in background.
  8. 1:01 Open the notification to read the delivered message.
  9. 1:15 Return to Settings to stop instant mail.
  10. 1:33 Manual checking selected. Foreground service and ongoing notification stopped.

Declaration context

Google requires a video showing the user steps that trigger each foreground-service feature. Foreground services must be user initiated or perceptible, user stoppable, and justified for the use case. The specialUse declaration remains subject to Google review. Sources: FGS declaration guidance, FGS use policy, Android specialUse documentation.
