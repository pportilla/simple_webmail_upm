UPM Mail: interactive demo and reviewer guide

Developer: zango · Package: io.github.pportilla.upmmail · Verified 25 October 2026 (Europe/Madrid)

For version 1.0.3 (version code 6). Focused checks of the exact signed build on Android 16 on 25 October 2026 verified clearer read/unread rows in light and dark themes, dynamic colors, selected read/unread messages, previews disabled, search results and changing read state by opening a message. These checks used the fictional adult sample mailbox. Unread rows now have a tinted background and a leading accent, alongside bold text and the unread dot.

Earlier mail and guardian verification: version 1.0.2 (version code 5). The exact version-5 signed build was checked on Android 16 on 25 October 2026: retained queued sends, fresh offline replies, attachment export, draft persistence, search, under-13 setup, wrong-PIN rejection, separate exact-message approval and guardian locking after Home. What the sample mailbox does

UPM Mail is an independent, unofficial email client. Normal use connects to the user's own authorized UPM or compatible TLS IMAP/SMTP mailbox. The app does not create a University account.

Try sample mail opens a fictional mailbox on the device without a mailbox username, password, one-time code or developer approval. This option is available through the normal setup interface. The account is labeled Sample · review@example.invalid. Sample messages and addresses are fictional. Mail actions performed with that account are simulated locally: a sample message shown as sent has not been delivered to a person or mail provider. Use fictional content while reviewing it.

The demo keeps the normal age, acceptable-use and guardian controls. The reviewer chooses their own local guardian PIN when testing supervision. There is no shared guardian PIN or personal mailbox credential on this page.

1. Open the adult sample mailbox

  1. Use an isolated test installation of the build containing the demo. On Who will use this app?, enter a fictional adult test date of birth, read the acceptable-use rules and select Continue. The date is used locally to derive the age band.
  2. On the mailbox setup screen, select Try sample mail (Probar correo de ejemplo in Spanish). Leave the real mailbox credential fields empty.
  3. Read the demo notice and open its inbox. Check that the selected sending account is the sample mailbox before composing.
  4. Compare the unread rows' tinted background, leading accent, bold text and dot with read messages. Open an unread message, then return to see its normal read appearance. The same styling appears in search results; selecting an unread row retains its accent.
  5. Read a sample message, star it, move it between folders or delete and undo deletion. Try the sample conversation, Drafts, Archive and Projects folders, and search. The fictional attachment is sample-notes.txt.
  6. Compose or reply to tutor@example.invalid or alex@example.invalid using Simulate send. In the adult interface, the sample backend creates a local Sent copy and a fictional tutor reply. To inspect failed-outbox recovery, send a new fictional message to fail-once@example.invalid: a sample message to this address fails once, then its retry succeeds locally. Reusing identical message content may reuse the successful result; change the subject or text to repeat the failure exercise.
  7. Open Settings to inspect appearance, language, notification options, account controls and the in-app privacy policy. English and Spanish are included in the app.

Try a local arrival and notification

  1. In the adult profile, open Settings → Notifications. Enable New mail notifications, allow notifications in Android, and set Check for new mail to Instantly (push). In the sample account's settings, also enable its notifications.
  2. In Settings → Sample · review@example.invalid, select Receive sample mail in 5 seconds. Return to the inbox or Android Home while the app process remains running. After the local delay, the app creates fictional mail and refreshes it locally; the usual notification settings and Android restrictions apply.
  3. With Only when I open the app selected instead, refresh the inbox after five seconds to load the new sample. In a supervised profile, the guardian checks the new message; it remains hidden from the child until approved, and no mail-content notification is shown.

This exercises local arrival, refresh and notification behavior. No message arrives from the Internet, no server connection is opened for the sample, and a sample-only installation does not start the persistent foreground service. If Android ends the app process during the delay, reopen the app and request another sample arrival.

2. Set up a supervised test profile

  1. From the adult interface, select Safety and family controls, then Set up this device for a child.
  2. Enter a fictional child test date of birth. The app routes users under 18 to supervised mail.
  3. On A parent or guardian must set this up, enter a fictional adult test date, choose a private PIN of at least six digits and enter it twice. Read the provider authorization acknowledgment and acceptable-use rules before accepting them. For this isolated test, the mailbox is the app's fictional local sample.
  4. Select Set up supervised mail. The child home starts locked with communication paused. Select Ask my parent or guardian and unlock using the PIN you just chose.
  5. In Guardian dashboard, enable Allow reviewed communication. This does not automatically expose incoming mail or authorize outgoing messages.
  6. If starting directly with a supervised profile instead of the adult walkthrough, first unlock the dashboard, choose Manage mailbox accounts, then select Try sample mail on setup. No real mailbox credentials are needed.

These DOB declarations and the PIN are local controls. They do not independently verify adult identity, parental authority or legal consent.

3. Review incoming mail and safety controls

  1. In Incoming messages to review, open a fictional sample message. Review the sender's exact address and complete text.
  2. Select Approve this contact, then Approve this exact text for the child. An approved address alone is insufficient.
  3. Use Finish guardian session to return to the child home. The approved message appears under Messages reviewed for you; unapproved messages stay hidden.
  4. Open the approved message. The child can select This message worries me to save a local concern, or Stop messages from this sender to strengthen restrictions.
  5. Unlock the dashboard again to review the concern, manage blocked contacts, pause communication or select Revoke all message approvals. Leaving the app or pressing Back locks guardian access. Guardian screens intentionally prevent screenshots.

4. Review an outgoing sample message

  1. On the child home, choose Write a message. Select the sample sending account and one approved fictional contact.
  2. Enter a fictional subject and message. Read the safety reminder and select Ask to simulate sending.
  3. Enter the guardian PIN. Review the exact recipient, subject and complete message, accept the exact-message acknowledgment and select Approve simulation.
  4. For the sample account, sending is a local simulation. Nothing is sent to the recipient or a provider. The normal live-account send path requires the user's own authorized mailbox.

Supervised reading and writing use plain text. Child attachments, clickable links, remote images, sharing, device-contact import and unrestricted search are unavailable. An adult can separately inspect the provider-report form; any report submitted from the sample account is simulated and does not reach a provider or moderator. Newly generated sample replies still require guardian review before the child can read them.

Scope, reset and data handling

  • The demo is not a UPM authentication test or evidence of delivery through an external provider. It does not establish Google approval or guarantee acceptance of this review route.
  • Real instant push requires a connected mailbox. For sample mail, the same setting enables local refresh after a requested sample arrival; it does not start an IMAP connection or a persistent foreground service. The separate verified foreground-service demonstration for version 1.0.2 (code 5) uses the exact signed version-5 APK with a separately configured local TLS IMAP/SMTP fixture and fictional mail. Version 6 changes row styling and leaves this service unchanged; this recording remains version-5 evidence. It shows user opt-in, an ongoing notification, background arrival, opening the delivered message and stopping the service. It does not use this built-in sample backend or establish UPM authentication, external-provider delivery, reusable reviewer mailbox access or Google approval.
  • Local sample-mail actions do not transmit messages to a mail server. Explicit browser, export or Android sharing actions retain their normal behavior; use fictional data and review the selected destination.
  • Other connected real accounts continue their normal network activity. They still use the data flows described in the privacy policy. The presence of an offline demo does not make the app a no-data-collection application.
  • Two shared screens retain generic server wording. In the sample account, search results labeled From server come from the local simulation. The account-removal confirmation mentions mail remaining on a server; removing a sample account actually deletes its local sample mailbox. No sample mail is stored on a UPM server.
  • To reset the sample mailbox, open Settings, select its account and choose Remove account. Add sample mail again to recreate the fictional messages. Selecting Try sample mail while the account already exists reopens it. In a supervised profile, first unlock guardian access and select Manage mailbox accounts. Removing the sample account does not remove other accounts.
  • For a completely fresh age/guardian test, clear app storage only on an isolated test installation. This removes that installation's local accounts, drafts, queued messages and controls. There is no guardian PIN recovery. Do not clear a user's real installation merely to restart this walkthrough.
